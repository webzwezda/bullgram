# Правило копирайта первого экрана site-v2

## Урок (2026-09-12, герой главной)

После переключения героя на одну кнопку «Купить готового юзербота» я предложил вернуть в trust-row пункт «Выделенный прокси на юзербота» как «сильный продающий пункт». Владелец объяснил: **не усложняем перечислением фич (прокси, API, MCP и т.п.) на первом экране** — они есть в продукте, но кричать о каждой фишке нельзя, покупатель запутается. По факту человеку нужно одно: купить и получить готовое и нормально работающее.

## Правило

- Первый экран продаёт ОДИН исход: покупка → всё готовое и работает. Никаких списков технических фич рядом с CTA.
- Прокси, API, MCP, safe-mode и прочая инфраструктура — для документации и глубоких секций, куда человек приходит уже подготовленным.
- Не предлагать «вернуть фичу в герой» в future итерациях без явного запроса владельца.
