## 1. Мини-волна: mono-шрифт и preload на site-v2 — ЗАВЕРШЕНО (153ee1d, деплой 2026-09-16)
**Решение.** site-v2 использует `font-mono` в 5 местах, и все — платёжные (memo, адрес кошелька, секрет счёта). Токен `--font-mono` уже отдаёт стек JetBrains Mono, но шрифт на сайте не подключён → рендер по локально установленному или ui-monospace. Решение то же, что в admin (волна 6b): копия двух woff2 в `public/fonts/` + алиасные @font-face с `/` (base сайта корневой) + preload Manrope ×2 в index.html (CLS на холодной загрузке).
**Приёмка:** билд зелёный; ratchet поймал +2 font-family (литеральные имена в @font-face — var() запрещён спекой) → осознанный baseline; на проде JBM @font-face зарегистрированы, woff2 200, preload ×2 в HTML. JBM не preloadится сознательно — нужен только на платёжных экранах (~52 КБ на остальных страницах лишние).

## 13. Роутер — хвосты наблюдаемости (2026-09-16)
**Паузы юзерботов не видны владельцу.** `tg_accounts.dm_paused_until/dm_pause_reason` пишутся роутером (flood → ~1ч, spam/флаг → 24ч), но ни один экран не показывает «юзербот на паузе до …». Владелец видит это косвенно: ёмкость на шаге «Юзерботы» считает по элигибельным, кампания с пустым пулом падает с queue_error.
**Решение.** Бейдж «на паузе до HH:MM (причина)» в списке юзерботов /app/userbots + в блоке пула на шаге «Юзерботы» рассылки; данные уже в tg_accounts. Мелочь: `getActorPause` в роутере читается без owner-скоупа (в отличие от pauseActor/clearPause) — доунифицировать при касании.
**Владелец:** оркестратор → фронт/бэк слайс. **Триггер:** первая жалоба «почему юзербот не шлёт» или следующее касание /app/userbots.
**Тоже в хвосте:** prod-проход по браузеру владельца (ёмкость, «Стоп», чипы — browser doctrine); e2e первой реальной рассылки: flood у актёра → строка остаётся pending → догонка следующим тиком; warmup-профили для новых юзерботов (пониженные капы первые N дней).
