# План: устранение находок критика по герою (2026-09-12, раунд 2)

Вердикт критика: CONDITIONAL PASS (лучше, чем до упрощения). Решения приняты владельцем делегированы агенту.

## Факты, снятые с прода и кода
- `/app/userbots` для покупателей (`profile_role !== 'admin'`) рендерит `UserbotStorefrontSection` («Магазин аккаунтов», бандлы, «Купить за N TON») ПЕРВЫМ экраном (BotsAccountsPage.jsx:448-450). Админ (Илья) видит визард — это админский вариант страницы, не баг воронки.
- → Условный Critical «обещание ломается на приёмнике» СНЯТ. Якорь/глубокая ссылка не нужны.

## Решения
1. Trust-row «REST API» / «MCP» — УДАЛИТЬ целиком (жаргон не гарантирует ничего; принцип «один исход»). H1 не трогаем: «с API и MCP» — идентичность продукта, остаётся единственным упоминанием на экране.
2. Подзаголовок: убрать имена инструментов («при помощи AI-Hermes или n8n»), вторую ветку укоротить до «или подключи свой».
3. Тарифы: добавить строку-разграничитель «Тариф — это доступ к кабинету. Готовые юзерботы покупаются отдельно и приходят готовыми к работе.»
4. Обёртка CTA (`gap-3` с одним ребёнком) — убрать, классы на кнопку.
5. admin-v2 не трогаем.

## Проверка
Сборка site-v2 → пуш → деплой → клик по кнопке на проде в Chrome → скриншоты → повторный design-critic (с код-фактом про витрину покупателя).
