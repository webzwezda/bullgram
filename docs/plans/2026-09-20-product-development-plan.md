## Цель и метрики

**Цель-2026:** первый внешний платящий клиент (≥1 оплата 10 TON), затем 5 и 10 платящих.
Это цель валидации спроса, не выручки: доказать, что незнакомый человек платит за исход
«агент читает Telegram за тебя».

Ворота (проходим по порядку, не по датам):
- **G1** — внешний пользователь получил первую автоматическую сводку (не руками владельца)
- **G2** — 10 внешних пользователей прошли активацию (подключил группу → получил сводку)
- **G3** — первая оплата 10 TON
- **G4** — 5 оплат → решение: вкладываться в рост или менять предложение
- **G5** — 10 оплат → пересмотр цены (10 TON/365 дней — осознанно дёшево до валидации)

## Зафиксированные решения (не пересматриваются внутри плана)

1. Витринный исход — **AI-сводки Telegram-групп**; пэйвол/автопост/магазин — модули, не тейк.
2. Дев-тир — MCP + API к юзербот-сессиям, продаётся на той же витрине.
3. **Сначала русский интерфейс**, EN-волна — отдельно (M4), когда RU-валидация даст сигнал.
4. Оплата **только TON** (10 TON / 365 дней Pro, Trial бесплатный). Фиат не возвращаем.
5. Юзербот-правила не ослабляем: прокси 1:1, safe-mode, manual-by-default, публичные группы.

## Отправное состояние (2026-09-20)

- Внешних клиентов: 0. Продаж не было. Лендинг перестроен под новый тейк (2026-09-19,
  ревью+критик пройдены) и **обещает self-serve сводки, которых ещё нет** — главный долг.
- Пайплайн сводок владельца работает ежедневно: n8n → `daily_digests` (утро/вечер,
  последняя — 2026-09-19). Продукта из него нет: внешнему юзеру он недоступен.
- Инфраструктура готова на ~80%: юзербот-чтение групп (MCP fetch-messages), планировщик
  (autopost scheduler), официальный бот (доставка в ЛС), биллинг (TON-инвойсы), лимиты
  (api_usage_monthly). Нет: LLM-шага в бэкенде, таблиц и UI сводок.

## Чего НЕ делаем (дисциплина фокуса)

- Не строим «конструктор-платформу» из июньской заметки (март-карта, не продукт).
- Не добавляем новые модули платформы (CRM, магазины, парсеры-конструкторы) до G3.
- Не трогаем цены, не заводим фиат, не делаем i18n-фреймворк до M4.
- Не расширяем админку «на всякий случай»: один экран `/app/digests` в M1, остальное по факту.

## M1 · Продуктизация сводок — закрывает долг лендинга

Оценка: 2–3 недели волнами (бэкенд → UI → e2e). Владелец: оркестратор; Эрик — операционка.
**Definition of Done:** владелец подключает группу через `/app/digests`, получает сводку
по расписанию в ЛС официального бота, без ручного n8n.

Бэкенд:
- [ ] Миграция: `digest_sources` (owner_id, userbot_id, chat_id, title, is_active),
      `digest_settings` (owner_id, schedule_time, timezone, delivery_bot_id),
      `digest_runs` (owner_id, window_from/to, messages_count, items jsonb, summary_text,
      delivery_status/error, sent_at) — форма `digest_runs` повторяет проверенную `daily_digests`
- [ ] `services/ai-digest.service.js`: LLM-суммаризация через OpenAI-совместимый API
      (plain fetch, без новых npm-зависимостей; ключ в `backend/.env`, провайдер конфигурируется;
      фича-флаг DIGEST_AI_ENABLED — без ключа сводка деградирует до «топ-N сообщений»)
- [ ] `jobs/digest.job.js`: тик раз в 5 минут по образцу autopost-планировщика →
      выбрать наступившие слоты → чтение групп существующим userbot-сервисом (рефакторинг:
      вынести fetch-messages из MCP-слоя в общий сервис) → LLM → доставка в ЛС официального
      бота (юзер обязан нажать /start — онбординг это проговаривает)
- [ ] Лимиты в job и API: Trial — 1 группа, 1 сводка/день; Pro — без лимитов
- [ ] Офлайн-тесты по образцу test:autopost (слоты, окно, лимиты, деградация без AI)

admin-v2:
- [ ] `/app/digests`: подключение группы (выбор из диалогов юзербота), слот/таймзона,
      кнопка «прислать тестовую сводку», история последних прогонов с ошибками доставки
- [ ] Пустое состояние экрана = онбординг: «нажми /start у @бот, выбери группу, укажи время»

Валидация M1: тесты зелёные → деплой → e2e на контуре владельца (реальная сводка в ЛС) →
код-ревью + критик по standing rule.

## M2 · Первые живые пользователи (RU)

Оценка: параллельно с хвостом M1. Владелец: Эрик (руки) + оркестратор (метрики).
**Definition of Done (G1–G2):** 10 внешних юзеров получили первую сводку.

- [ ] Воронка в БД: события «register → /start бота → группа подключена → первая сводка»
      (использовать customer_funnel_events, добавить недостающие типы)
- [ ] Найти 5–10 живых RU-юзеров: чаты автоматизаций/n8n/крипто, личные сети после M3
- [ ] Фаундер-онбординг каждого (лично провести до первой сводки; чек-лист шагов в /app/digests)
- [ ] Лог возражений (таблица: возражение → ответ → изменили ли продукт) — файл в docs/plans/
- [ ] Править онбординг по логу, не по фантазиям

## M3 · Витрина-лидмагнит: публичный дайджест-канал

Оценка: дни, не недели — контур владельца уже выдаёт контент. Владелец: Эрик.
**Definition of Done:** публичный TG-канал с ежедневной сводкой и CTA на bullgram.xyz.

- [ ] CTA-строка в каждом посте: «Хочешь такие сводки по СВОИМ группам → bullgram.xyz»
- [ ] Закреп с объяснением, что канал — живая работа продукта

## M4 · EN-волна + дистрибуция в экосистемах

Триггер старта: G1–G2 пройдены, лог возражений стабилен (те же вопросы ≥3 раз) ИЛИ прямое
решение владельца. Оценка: 2 недели. Владелец: оркестратор (перевод и каталоги), Эрик (посты).

- [ ] Перевод site-v2 на EN (подход решить на входе: извлечение строк vs EN-копия лендинга;
      админка может остаться RU — решение владельца на чекпоинте)
- [ ] MCP-директории: регистрации в mcp.so, Glama, Smithery, PulseMCP (публичная дока
      эндпоинта уже есть — проверить/обновить под требования каталогов)
- [ ] n8n-шаблон «Telegram groups → AI digest» в community + пост (владелец — живой юзер)
- [ ] Публичный EN-дайджест-канал (клон M3 на англ. группах)
- [ ] Reddit/X build-in-public: кейс «22k вызовов агента за 2 месяца» (числа из прод-базы)

## M5 · Первые деньги и решение о масштабе

Владелец: совместно. Триггер: M4 активен, воронка считает конверсию.

- [ ] Кампания первых продаж: цель ≥1 оплата (G3) → 5 (G4) → 10 (G5)
- [ ] На G4 — решение: рост (больше дистрибуции) vs предложение (менять пакет/цену)
- [ ] На G5 — пересмотр тарифа Pro (10 TON/365д) и, возможно, месячного тира
- [ ] Только после G5 — вернуться к отложенным модулям (пэйвол-витрина, магазин, CRM)

## Риски и как держим

- **Баны юзерботов на чтении групп** — только публичные группы, прокси 1:1, новые аккаунты
  через safe-mode, SpamBot-мониторинг как источник истины (правила уже в AGENTS.md).
- **Стоимость LLM** — Trial жёстко лимитирован (1 группа/1 сводка), кэш промптов, деградация
  без AI-ключа до «топ-N сообщений».
- **Крипта-барьер для RU** — осознанно; сегмент крипто-нативен, фиат не возвращаем до G5.
- **Время соло-владельца** — вехи идут по Definition of Done, не по календарю; оценки в
  неделях ориентировочные; M2/M3 делаются руками владельца в фоне, пока идёт M4.
- **Обещание без продукта** — лендинг уже обещает сводки; пока M1 не закрыт, привлекать
  трафик на главную нельзя (иначе жжём первых посетителей). M3-канал можно — он сам продукт.
