# Окно поднятия прокси над панелью подключения аккаунта

Дата: 2026-10-23. Статус: в работе. Владелец одобрил план устно («делай»).

## Задача

В окне подключения аккаунта (шаг 1 «Выбор прокси») сузить селект, добавить
кнопку «Подключить прокси»; по ней над окном подключения появляется окно
поднятия прокси — фронт со страницы `/userbot/proxies`.

## Решение (согласовано с владельцем)

- `/proxies` (ProxyManagerPage.jsx) НЕ редактируется. Новый самодостаточный
  `ProxyConnectPanel.jsx` — дословная копия обеих карточек страницы:
  админская «Поднять серверный прокси» (серверное поднятие + для себя/на
  продажу + цена + количество + внешний прокси) и клиентская «Добавить свой
  прокси» (host/port/auth + квота-лок). Свой fetch `/api/userbot/proxies`
  при открытии (support, подсказка имени «Прокси #N»).
- Известная цена (владелец согласился): логика saveProxy дублируется —
  страница + панель; будущий рефактор — вынос общего компонента с правкой
  страницы.
- `UserbotOnboardingSection`: опциональный проп `onConnectProxy` — без него
  селект на всю ширину как раньше (/connect пиксель-в-пиксель), с ним —
  компактный ряд: селект flex-1 + кнопка «Подключить прокси».
- Связка после успеха: панель прокси закрывается → `reloadAccounts()`
  обновляет списки страницы → созданный прокси (`proxy_ids[0]`) подставляется
  в шаг 1 окна подключения (`preferredProxyId` + effect в UserbotConnectPanel).
  Для shop_sale лотов прокси на витрину — в селект он не попадает (не
  available), авто-подстановка тихо пропускается.
- Роли: админ видит серверное поднятие; не-админ — только внешний прокси
  руками, при отсутствии квоты — лок (тексты страницы сохранены).

## Ревью (2026-10-23)

Сделано по согласованному плану. Коммит beeaf99: новый ProxyConnectPanel
(~560 строк — обе карточки + saveProxy + квота-локи + подсказка имени),
компактный шаг 1 по опциональному пропу (без пропа разметка байт-в-байт
прежняя — /connect не менялся), связка через preferredProxyId в секции.
Прод-верификация агентом не проводилась: владелец забрал проверку браузера
на себя (инструкция 2026-10-23 «не проверяй браузером, я сам посмотрю»).

Что проверить владельцу на проде (/userbot → «Подключить аккаунт»):
1. Шаг 1: селект уже, справа кнопка «Подключить прокси» (на мобилке — столбиком).
2. Кнопка открывает окно «Поднять серверный прокси» НАД окном подключения;
   бейдж с подсказкой имени, «для себя/на продажу», цена при «на продажу»,
   количество, переключение на внешний прокси, крестик.
3. Поднять тестовый прокси «Для себя» → тост, окно закрылось, прокси выбран
   в шаге 1. (Вариант «На продажу» — уйдёт на витрину, в шаг 1 не подставится.)
4. /proxies и /connect ведут как раньше.

Долг, зафиксированный в плане: saveProxy дублируется (страница + панель);
правки логики создания прокси до выноса общего компонента нужно вносить
синхронно в оба места.

## Заметка по ratchet

Копия страницы приносит raw-классы (slate/blue/violet/...) — hardcodes-ratchet
вырастет. Решение: осознанное `--update-baseline` с обоснованием в коммите
(дословная копия живого прод-экрана; семантическая миграция копии — вместе с
будущим выносом общего компонента). Запись в design/CHANGELOG по прецеденту
1.1.0.
